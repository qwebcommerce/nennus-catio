# T7: Customer website and staff UI (system/client) against the live API

Scope changed partway through. The first scope was `nennuscatio-frontend-main/`. Notes on that before the change: it was run on Node 24.22.3 with pnpm 11.19.0, both installed locally in the scratchpad through npm. contracts:check, biome lint, typecheck, 573 vitest tests and the Next build all passed. Its API (`/api/admin/*`, `/api/checkout`, `/api/bookings`, cookie auth, a `{code,message}` error envelope) does not exist in system/server: those paths return 404 or 401, and none of the bodies match its Zod contracts. Per the coordinator, that app is only a design reference, so that work was dropped and its dev server was stopped.

## Setup used
- I copied `system/client` to `scratchpad/tests/T7/client`, so no repo files were changed. Vite dev ran with `node node_modules/vite/bin/vite.js --port 5150 --strictPort`. The repo's vite.config.js already proxies `/api` to localhost:4000, so it was used as is. The server has since been stopped.
- `npm run build`: **PASS**. It built in 6 s and generated the PWA service worker. The only warning was that the main chunk is 890 kB. **The client has no lint or test scripts**, so there was nothing else to run.
- Playwright (Chromium) scripts are in `scratchpad/tests/T7/*.js`. Screenshots are in `scratchpad/tests/T7/shots/`.
- Test data I created: customer `t7-1794834850750@test.local` (password T7password!, verified through the dev verify link) with pet T7-Mishmish and address T7 Street 1. Also one relocation request "T7-London, UK", one attempted guest checkout (T7-Guest, auto-cancelled) and one attempted grooming booking (auto-cancelled).
- WebKit and Firefox are not installed here, so only Chromium was run. External images (unsplash) fail with ERR_TUNNEL in this sandbox; that noise is ignored below.

## UI flows that call failing or missing API routes
- `POST /api/shop/checkout` and `POST /api/shop/grooming/book` both return 400 `{"error":"fetch failed"}`. The SkipCash host cannot be reached from the sandbox, so this is an environment issue. But the raw text "fetch failed" reaches the customer. The backend cleans up correctly: the sale and the booking go to CANCELLED.
- `GET /api/shop/me`, `/api/shop/orders` and `/api/shop/relocation` return 401 for guests on every visit to /shop/account, /shop/orders and /shop/relocation. This is expected, but it fills the console with errors.
- No 404s turned up in any customer or staff flow I ran. On load, all 18 staff pages showed no API errors.
- Staff console: React warning "Received `true` for a non-boolean attribute `inert`" from SidebarNav on every staff page.
- The email-verify and reset links default to `http://localhost:5173` (`routes/shop.js:16-20`, set by APP_PUBLIC_URL/CLIENT_URL). That is a configuration issue.
