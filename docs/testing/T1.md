## Top defects (by severity)

1. **Staff GET /api/customers exposes password hashes and token hashes** (NFR-11/12/15). The cashier token on `GET /api/customers?q=t1-cust1` returns `"passwordHash":"$2a$10$…"`, `verifyTokenHash` and `resetTokenHash`. Cause: customers.js:36 has no `select`.
2. **Deactivating or demoting staff does not revoke access, and deletion strips audit authorship** (FR-07, FR-10, NFR-16). As admin, create a MANAGER and log in as them. Then `PATCH /api/users/:id {role:"ASSOCIATE"}`: the old token still gets 200 on `/api/accounting/accounts`. Next, `DELETE /api/users/:id`: the token still works, and `PATCH /api/org-settings` returns 200 with **no audit row**, while the manager's earlier audit rows now have `userId=NULL`. A user who has made sales cannot be deleted at all (FK RESTRICT), and there is no deactivate flag.
3. **Staff-only pet notes leak to the customer** (FR-03, Private notes, NFR-15). As admin, `POST /api/customers/:id/pets {notes:"secret"}`. Then as the customer, `POST/GET /api/shop/relocation` with that pet. The response has `pets[0].notes = "secret"` (relocation.js:61).
4. **The module permission matrix is mostly unenforced, and owner-only rules are not owner-only** (FR-08/09/10, NFR-12). The cashier (purchasing/finance view = false) gets 200 on `/api/suppliers`, `/api/purchases` and `/api/dashboard/monthly-profit`. The cashier passes the role gate on `POST /api/online-orders/:id/status`. A MANAGER gets 200 on `PATCH /api/org-settings` and `PUT /api/loyalty-settings`. A non-owner ADMIN can edit roles and permissions.
5. **Session tokens are readable by page scripts** (NFR-11). Both logins return the JWT in JSON, the clients store it in localStorage (AuthContext.jsx:86, Shop.jsx:317), and there is no httpOnly cookie.
6. **No stale-edit protection anywhere** (NFR-13). No version field exists, and concurrent PATCHes both succeed.
7. **Unaudited stock set and access changes** (FR-88). `PATCH /api/inventory/:p/:b {quantity:77}` changes stock with no movement and no audit. User create, role change and delete write nothing.
8. **Dev-mode verify and reset links in the API response** (FR-01). These allow account takeover if deployed without `NODE_ENV=production`. Also: verify tokens never expire, a reset does not end old sessions, and an unverified registration overwrites a guest customer's name and phone.
9. **No profile edit or preferred language** (FR-02). `PATCH /api/shop/me` returns 404, and locale is not exposed.
10. **A signed-in customer can attach orders to another email** (FR-05). The body `email` overrides the session (shop.js:618), and a guest checkout can change an existing customer's locale.
